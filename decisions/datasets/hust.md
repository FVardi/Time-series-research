# Decisions — HUST bearing data (raw)

Dataset-specific decisions for the HUST bearing dataset (Hanoi University of Science and Technology; Thuan & Hong, 2023). Adopted in D189/D190, downloaded in D194. Index: `../../DECISIONS.md`.

## 2026-11-05 — D223: HUST conversion: literature standard, otherwise harness conventions
**Decision:** The conversion follows what the literature does; where the literature has nothing to say (how runs are stored), the harness's conventions apply (D1–D6, D31, as for CWRU D139 and Paderborn D212).
1. *Signal (literature):* only the steady-state vibration signal `data` (51.2 kHz) is converted, the signal the dataset authors use in their experiments (arXiv 2302.12533). The run-up recordings (`ru`, `ru_raw`, with `rpm`) are not converted; they stay in `data/raw/hust/`. The variables present but not converted are listed in each run's extras (`not_converted`).
2. *Hierarchy (harness convention):* one run per file (99 runs, run ID = file name, e.g. `I402`), one capture (`capture_0`), one stream (`accel`), one channel `vibration`.
3. *Labels (per-capture columns, D31), from the file name as the data note describes it:* `fault` (N, I, O, B, IO, IB, OB; the 7 classes of the authors' experiments), flags `inner_fault`, `outer_fault`, `ball_fault`, `bearing_type` (6204–6208), `load_w` (0, 200, 400), the bearing geometry from the data note (inner and outer diameter, ball diameter, number of balls), and `bearing` = fault + type (e.g. `IO6206`): one test bearing per fault type and bearing type, recorded at the three loads. File names are `<fault><bearing digit>0<load digit>`; the data note explains the two digits, the middle 0 is in every name.
4. *Telemetry:* `fs` as recorded, as `shaft_freq_hz` (the data note: "shaft frequency in Hz").
5. *Units, type, status:* units `unknown` (not stated in the data note or the files); sensor (PCB 325C33, vertical, on the housing; NI-9234, CompactDAQ, LabVIEW) in the run's extras; values 64-bit floats as in the files (D6); status `final`; licence CC BY 4.0.
6. *Raw folder:* kept as downloaded (D213): `data/raw/hust/HUST bearing a practical dataset for ball bearing fault diagnosis/HUST bearing dataset/` (99 `.mat` files) and two figures.
7. *Quirks, recorded in the run's conversion notes, not fixed:* recordings not of the stated 10 s (512,000 samples): 8 files have 512,001 samples (IO400–404, IB602, IB604, OB500–504), IB600 has 562,001, and 9 are shorter: B602, B604, B800, B802, B804, OB400, OB402 (121,082, the shortest), OB404, OB804 (all stored as recorded); IO602's `fs` (22.89 Hz) equals IO604's while the other 200 W files have 23.96–24.42 Hz (probably a copy error). Not affecting the converted data: the data note speaks of "27 prototype defective bearings and 3 healthy bearings", while the files hold 28 fault/bearing-type combinations and 5 healthy bearing types (B and IB are missing for 6204, as the note states); the run-up variables differ between files (46 have `rpm` and `ru`, 52 `ru_raw`, OB400 none), B602's `rpm` holds values down to −50,559,158. No NaNs, no two files with identical signals.
For the later split decision, the authors' protocols (arXiv 2302.12533): (a) 7-class classification, 2,048-sample windows with 75 % overlap, random 80/20 split; (b) leave-one-bearing-type-out transfer, classes N, I, O, B, targets 6205–6208, 4,096-sample windows without overlap, mean over five runs.
**Alternatives considered:** Converting the run-up recordings as a second capture per run (not used in the literature; variables inconsistent and not explained). Channel named `data` as in the files (uninformative).
**Rationale:** User's decision (2026-11-05): do what is standard in the literature, so there are fewer decisions and results are easier to compare. Items 2 and 6 have no literature standard and follow the harness's conventions (Claude's choice).

*Note (2026-11-05): conversion done (`harness/data/hust.py`, `scripts/convert_hust.py`, test `tests/test_hust.py`): 99 runs in `data/canonical/hust/`, 360 MB. Values checked identical to the source files for 7 files chosen for their quirks (test). Run on the Linux side with a separate environment (scipy, h5py, pandas, pyarrow).*

## 2026-11-05 — D226: HUST task and split: the dataset authors' 7-class classification experiment
**Decision:** HUST is evaluated with the classification protocol of the dataset authors (Thuan & Hong, arXiv 2302.12533, Section 4.3), the one split for HUST:
1. *Classes:* seven, the fault code (N, I, O, B, IO, IB, OB), as their experiment ("7 fault statements of 5 types of bearings").
2. *Data:* all 99 recordings (all five bearing types and the three loads). Not stated in the paper and therefore inferred, marked as such: which loads they used (they name none); all are used.
3. *Windows:* 2,048 samples (about one shaft revolution) with 75 % overlap (a hop of 512 samples), cut from the start of each recording, the incomplete last window dropped (as D137).
4. *Draw and split:* 2,500 windows per class drawn at random (17,500 in total), then a random 80/20 split stratified by class (14,000 training, 3,500 test windows), as their "randomly select 17,500 segments … (each fault has 2500 segments)" and "training sets (80%) and test set (20%)". Their seed is not given; the draw and the split use `random_state` 0 (Claude's choice), fixed for all seeds (as D174). Not stated whether their split is stratified; stratified is used, as on CWRU (D171), since the classes are equal in size anyway. Because windows overlap and the split is by window, training and test windows from the same recording share samples, as in their protocol.
5. *Harness conventions (no literature standard; the authors use hand-crafted features and end-to-end models):* pretraining on the training windows (as D164); per-channel standardisation with the pretraining windows' statistics (D137); label budgets 1 %, 10 %, 100 % (D40, drawn as D138; 1 % = 140 windows, 20 per class); `logreg` probe (D133) with plain stratified 5-fold cross-validation (as D175, random split).
6. *Code:* `harness/windows.py` gets two optional settings, unused by every existing config: `windows: hop` (window step; default the window length, i.e. no overlap as before) and `split: random_windows: per_class` (windows drawn per class before the split). `harness/labels.py` gets `hust`.
**Alternatives considered:** The authors' leave-one-bearing-type-out transfer experiment (classes N, I, O, B; 4,096-sample windows without overlap; targets 6205–6208), which tests unseen bearing types, the reason HUST was adopted (D189); the follow-up paper's setup (Thuan, Hue & Hong 2023, IJACSA 14(5): 6205–6207, no load, 4,096-sample windows with 75 % overlap, nine source/target tasks).
**Rationale:** User's decision (2026-11-05): use the literature standard; of the authors' two protocols, the classification experiment chosen (Claude's recommendation: the dataset paper's main experiment, a random window split like CWRU's Zhao protocol; transfer setups differ between papers, even between the authors' own).
