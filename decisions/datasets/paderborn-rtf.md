# Decisions — Paderborn run-to-failure data (time-varying conditions)

Dataset-specific decisions for the run-to-failure data set of ball bearings subjected to time-varying load and speed conditions (Chair of Dynamics and Mechatronics (LDM), Paderborn University; Aimiyekagbon, 2024; https://doi.org/10.5281/zenodo.10868257; CC BY 4.0; cite Javanmardi et al., 2024, PHM Society European Conference 8(1), doi 10.36001/phme.2024.v8i1.4101). Adopted by D234. Not the Paderborn KAt fault data (`paderborn.md`). Index: `../../DECISIONS.md`.

## 2026-11-05 — D235: Download one experiment at a time, convert, then delete its archives (exception to D194 and D213 for the vibration files)
**Decision:** `scripts/download_paderborn_rtf.py --out data/raw/paderborn_rtf --convert-to data/canonical` processes one experiment at a time: it downloads the experiment's ZIP parts from Zenodo (MD5-checked against the records API), converts them (D236; the converter reads the archives directly and checks the written HDF5 file against the written codes), unpacks the experiment's small files (`Bxx_log.pdf`, `Bxx_operatingConditions.csv`, `Bxx_meanTemperatures.csv`, anything else outside `vibrationData/`) unchanged into `data/raw/paderborn_rtf/Bxx/` (the archive's layout, D213), and only then deletes the ZIP parts. The description PDF (`LDM_UPB_Run-to-failure_data_set_of_ball_bearings.pdf`) is kept as downloaded. The raw vibration `.mat` files are therefore not kept on disk; Zenodo (DOI, immutable record) is their archive, and the script can download any experiment again.
**Alternatives considered:** Keeping all 48 ZIP parts (152 GB) or the unpacked files (about 170 GB, estimated from B01's ratio of 1.13) next to the canonical data (does not fit the 189 GB free on the work computer). Channel A only (the channel the authors analyse; halves the size but drops channel C). A subset of experiments (breaks the authors' protocol, D234). Keeping every k-th measurement (changes the data and the remaining-useful-life labels).
**Rationale:** User's decision (2026-11-05), following Claude's recommendation. The canonical int16 codes (D236) hold the recorded information (D6) in about a quarter to a third of the space (B01 test: 0.6 MB per measurement for both channels, against 2.6 MB in the archive); peak disk use is the converted data plus one experiment's archives (at most about 30 GB, B06 and B15). Deletion only after a successful, checked conversion; any problem stops the script with the archives kept.

*Note (2026-11-05): the multi-part archives have the top folder `Bxx_part<k>/` (e.g. `B06_part1/`, with the log and CSVs in part 1), not `Bxx/`; their small files are unpacked into `data/raw/paderborn_rtf/Bxx/` like the single archives', so every experiment has the same layout. Dropped connections during the download are retried automatically, resuming from the `.part` file (B06_part2 was cut off at 5.76 GB on the first run).*

## 2026-11-05 — D236: Conversion: dataset documentation, otherwise harness conventions
**Decision:** As for XJTU-SY (D224), the dataset's documentation is followed where it says something, otherwise the harness conventions (D1–D6, D20, D31). Sources: the description PDF (v2, 2024-03-25; "description") and the experiment logs. Code: `harness/data/paderborn_rtf.py`, `scripts/convert_paderborn_rtf.py`; test `tests/test_paderborn_rtf.py` (synthetic two-part experiment; ZIP → HDF5 → `load_signal` exact; off-grid values stop).
1. *Hierarchy:* one run per experiment (run ID `B01`…`B17`); each `.mat` file (one 1.6 s measurement) one capture, `m00001`… (measurement number, five digits, since B15 has 22,567); one stream `accel` (A and C share the acquisition).
2. *Signals:* the two channels provided, names as the files' variables, `accHorizRear_A` and `accHorizFrontal_C` (description 2.2; accelerometer B is not in the data set). Sample rate 128 kHz for B01–B09 and 64 kHz for B10–B17 (description Section 2), 1.6 s per measurement; every file is checked for these lengths.
3. *Storage as ADC codes (D6, D20):* the values in the files are volts on the fixed grid of the 16-bit NI-9223 (checked on B01 M0001 and M0377: deviations from the grid below 1.2e-7 steps). Stored as int16 codes with per-run, per-channel scale (step) and offset; physical value = code × scale + offset. The constants are fitted on the experiment's first measurement and snapped to the round decimal the instrument uses (B01: A 0.000323335 V and −7.2113e-05 V; C 0.000323356 V and −0.0001208 V). Every file is checked: a value more than 1e-6 steps off the grid, a code outside int16, or a reconstruction further than 2 ulp of the file's largest absolute value from the source stops the conversion. On B01, channel A is reconstructed bit for bit; channel C within 1 ulp of the file's largest value (at most 4.4e-16 V; the instrument's own floating-point scaling for C could not be reproduced exactly). gzip level 4, chunks of 16,384 (D21, D23).
4. *Time:* `measTime` is not stored (D6): it is checked in every file to equal sample index / sample rate within 1e-9 s. Capture start time: seconds since the experiment's first measurement, from the `Time` column of the operating-conditions CSV (1 s resolution, local time of the rig), with `timing_accuracy` saying so.
5. *Telemetry (D2):* one row per capture with every column of `Bxx_operatingConditions.csv` and `Bxx_meanTemperatures.csv` under the source's column names (e.g. `setSpeed / rpm`, `meanAbs_statLoad / N`, `Mean Abs. Temp. T1 / °C`), numbers parsed with Python's `float()` (D224 note). Rows are matched to measurements by order; the conversion stops if the row counts differ from the number of files or the two CSVs' timestamps differ.
6. *Per-capture columns (D31):* experiment, measurement number, `date_time` (verbatim), defect and threshold criterion from description Table 3 (verbatim, e.g. `IR, OR, B`, `Tvibration`, `-`). No derived labels: transition time, remaining useful life and the handling of the warm-up phase are task decisions.
7. *Run extras:* Zenodo DOI, Table 3 (duration, number of files, threshold criterion, defect), Table 2 ranges (speed, static load, dynamic load amplitude, excitation), bearing characteristics (Table 1), sensors, stop criterion, conversion notes. Units `V` as recorded (D5); the g/V conversion factor and gain are in each experiment's log (B01: 10 g/V, 0 dB; the description gives 100 mV/g for the PCB 603C01), kept in `data/raw/paderborn_rtf/Bxx/`; conversion to g is a pipeline step.
8. *Status and source:* `final` (public benchmark, D7). Source identification (D24): archive names, total size, latest modification time; the archives themselves are deleted (D235).
9. *Quirks:* recorded, not fixed: a file count differing from Table 3, files other than the documented ones, timestamps out of order. An unexpected variable set, sample count, time array, gap in the measurement numbering, CSV row count, or anything off the ADC grid stops the conversion. Known from B01 and its log, not handled by the converter: measurements 1–55 are the 10-minute warm-up (750 rpm, 2,500 N, no dynamic load) outside the Table 2 ranges; the measurement interval is not constant (about 12 s at the start, about 30 s later); Table 3 lists no threshold criterion for B01, while its log says the experiment ended because the temperature threshold was exceeded (the log's end time, 9:13, is earlier than the last measurement, 10:59:32); the description names a `Bxx_extractedFeatures.csv` that B01.zip does not contain.
*Multi-part archives (note 2026-11-05):* member names `Bxx_part<k>/...` are normalised to `Bxx/...` to find the measurements and documents across parts (folder entries ignored); the captures table's `source_name` keeps the archive's own member name, e.g. `B06_part2/vibrationData/data_B06_M02501.mat`. B06's measurement files are numbered with five digits (`M00001`).
**Alternatives considered:** 64-bit floats as in the files (bit-exact for both channels, about 3× the size late in a run; D6 prescribes codes for quantized sources). Channel C as float64 and A as codes (mixed storage for one quantization). Resampling B01–B09 to 64 kHz at ingestion (a transformation, D5). One run per measurement.
**Rationale:** User's decision (2026-11-05): delegated to Claude's recommendations, staying with the literature standard and the project's decisions. The integer codes are what the ADC recorded (D20's rationale); the 1-ulp difference on channel C is far below one ADC step (about 1e-12 steps) and below float64 resolution of the signal's range.

*Note (2026-11-10): conversion of all 17 experiments completed by the user (36 GB in `data/canonical/paderborn_rtf/`); every archive deleted after its checked conversion; `data/raw/paderborn_rtf/` holds the description PDF and B01–B17 with log and CSVs. No conversion notes in any run: file counts as in description Table 3 (95,660 measurements), no undocumented files. Every file passed the grid and reconstruction checks with the same ADC constants in all 17 runs (A: 0.000323335 V, −7.2113e-05 V; C: 0.000323356 V, −0.0001208 V). All 17 logs: conversion factor 10 g/V, gain 0 dB; sampling frequency 128 kHz (B01–B09) and 64 kHz (B10–B17), as in the description.*
