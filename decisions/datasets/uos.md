# Decisions — UOS multi-domain vibration data (University of Seoul)

Dataset-specific decisions for the multi-domain vibration dataset with various bearing types under compound machine fault scenarios (Data in Brief 57 (2024) 110940, doi 10.1016/j.dib.2024.110940; Mendeley Data 53vtnjy6c6, 7trwzz77xh, 2cygy6y4rk for subsets 1–3). Adopted by D189/D190, downloaded by D194 (all three subsets in `data/raw/uos/`). Index: `../../DECISIONS.md`.

## 2026-11-10 — D248: UOS conversion
**Decision:** The data paper is followed where it says something, otherwise the harness conventions (D1–D6, D31), as for HUST (D223). Code: `harness/data/uos.py`, `scripts/convert_uos.py`, `harness/data/quantized.py`; tests `tests/test_uos.py`.
1. *Hierarchy:* one run per file (1,152 runs; run ID = file name, e.g. `H_IR_8_6204_1000`): one recording at one speed and sampling rate; one capture, one stream `accel`, one channel `Data` (the files' variable).
2. *Signals:* `Data` only, in g (data paper), 1,280,000 points (160 s at 8 kHz, 80 s at 16 kHz). The authors' STFT products (`Spectrogram`, `STFTFreq`, `STFTTime`) are derived and not converted (D5); listed in the run extras.
3. *Storage as ADC codes (D6):* the values lie on a fixed grid (step 3.132768703465217e-06 g, offset 0 in the files checked; digital USB accelerometer). Stored as int32 codes (about ±900,000; too large for int16) with per-file step and offset, fitted by `quantized.grid_constants`. Every file is checked: a value more than 1e-6 steps off the grid, a code outside int32 or a reconstruction further than 8 ulp of the file's largest absolute value from the source stops the conversion. On the files checked, every sample is within 1 ulp of the source (4.4e-16 g); most samples differ by 1 ulp (the instrument's own floating-point scaling is not reproduced exactly). About 3.5 MB per file (about 4 GB in total).
4. *Per-capture columns (D31):* machine (rotating-component) condition H, L, M1–M3, U1–U3; bearing condition H, B, IR, OR; bearing model (6204, N204, NJ204 for IR faults, 30204) and type; speed (rpm, from the file name). Telemetry: nominal speed. Run extras: descriptions of the conditions (looseness half a turn; misalignment 0.6/0.8/1.0 mm; unbalance 3/4/5 g), bearing geometry (Table 2), sensor (PCB 333D01, ±20 g, on the shaft-end bearing housing).
5. *Checks before conversion (2026-11-10):* all 1,152 expected files present (8 machine × 4 bearing conditions × 2 rates × 6 speeds × 3 subsets), none extra; folders agree with the file names. A name, variable set, folder or NaN that is not as expected stops the conversion.
6. *Status and source:* `final`; D24 per file. Licence CC BY 4.0 (subset 1, D194; subsets 2 and 3 not checked).
7. *Task and split: open.* The data paper reports no experiment, and no protocol used across the literature was found (2026-11-10), so D216's order (official split, authors' protocol, most widely used protocol with open code) gives none. To be decided.
`harness/data/quantized.py` holds the grid code shared with Paderborn RTF (moved from `harness/data/paderborn_rtf.py`, behaviour unchanged; Paderborn RTF test passes); it also tries an offset of exactly 0 when the fitted offset is within float noise.
*Note (2026-11-10, after the first conversion attempt): the least-squares step was a few ulp off the instrument's step on the work computer (platform-dependent linear algebra), so the reconstruction of H_H_16_6204_1400 exceeded 8 ulp and the conversion stopped after 10 files. The step is now also taken exactly from the data (with offset 0, the smallest positive value is code 1 = the step, 3.1327687034652176e-06 g), and with it every sample of the files checked is reconstructed bit for bit (code × step equals the source exactly). The 10 runs converted with the fitted step are to be deleted by hand and reconverted, so that all runs use the exact step.*
*Note (2026-11-10, second attempt): the conversion stopped again after 171 files at M2_IR_8_6204_1200, which has no value with code 1 (its smallest positive value is 2 × step), so the exact candidate was missing and the platform-dependent fit was used. The step is now recovered from the few smallest values of both signs divided by their code (n ≤ 16); checked bit-exact on the five files staged, also with the least-squares step shifted by ±7 ulp. All runs are to be reconverted so that every run uses the exact step.*
*Note (2026-11-10, third attempt): U1_IR_8_6204_600 holds one stray value, -6.4455e-302 at sample 1,264,084, where every other value is on the grid; it is stored as code 0 (0.0, a difference of 6e-302 g, within the reconstruction check) and listed in the run's conversion notes, as any such value. The first guess of the grid step now ignores differences far below the median one, which this value had made 6.8e-304.*
*Note (2026-11-10, fourth attempt): L_OR_8_30204_1400 holds one value 0.053 steps off the grid (0.3739713 g, sample 73,436) among 1.28 million on it. Such files cannot be stored as codes; they are now stored as recorded, 64-bit floats (scale 1, offset 0; D6's rule that codes are only for exactly quantized data, applied per file), with the off-grid samples listed in the run's conversion notes; the other files stay int32 codes. The first step guess is now the median gap between distinct values, which a few stray values cannot move.*
*Note (2026-11-10): conversion of all 1,152 files completed by the user (4.1 GB in `data/canonical/uos/`). 1,149 runs are int32 codes with step 3.1327687034652176e-06 g and offset 0, bit-exact; U1_IR_8_6204_600 is int32 with its one stray value (-6.4e-302) stored as 0.0; M3_H_8_30204_800 (one value off the grid, -0.0310133 g at sample 220,690) and L_OR_8_30204_1400 (0.3739713 g at sample 73,436) are float64 as recorded. Found from the conversion notes of every run.*
**Alternatives considered:** 64-bit floats as in the files (bit-exact, about twice the size). One run per subset or per condition and speed (8 and 16 kHz files are separate recordings). Converting the spectrograms.
**Rationale:** User's decision (2026-11-10): approved Claude's proposals as given ("go ahead").
