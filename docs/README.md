# docs/ — current rules (D259)

The decision log (`DECISIONS.md`, `decisions/`) is the history: every decision in the order it
was made, superseded ones kept. These cards are the **current state** factorised by subject:
what holds now for the whole harness, for each method and for each dataset, with the D-numbers
that establish it. Settings themselves live in the config parts (`configs/datasets/`,
`configs/methods/`, D260), with their sources in comments; the cards say why and point there.

| card | what it holds |
|---|---|
| [protocol.md](protocol.md) | rules that apply to every dataset and method: data layer, splits, inputs, method settings, probes, metrics, seeds, runs, reporting |
| [methods/](methods/) | one card per method: source and commit, how it is integrated, departures from paper/code, per-dataset adaptations, findings, open points |
| [datasets/](datasets/) | one card per dataset: source, conversion, task and split, windows and inputs, probes and metrics, departures, open points |

Progress (what has run) is in `STATUS.md`, generated by `scripts/status.py`; to-dos are in the
project checklist; questions for the supervisor in `QUESTIONS.md`; ideas for the own method in
`METHOD_IDEAS.md`; candidate datasets in `DATASET_CANDIDATES.md`.

## Keeping the cards current (CLAUDE.md, D257)

- A decision that changes a current rule updates the card in the same change, and the card
  cites the new D-number. The decision log keeps the history; the card is rewritten, not appended.
- Choices taken from a standard (paper, official code, dataset authors' protocol, common
  convention) need no D-entry: they are written in the config with their source and, where they
  matter, in the card under "Standard choices" with the source.
- A card says "open" for anything not yet decided; nothing is filled in by guess.
